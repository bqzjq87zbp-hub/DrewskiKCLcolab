# Mobile loading and recovery

The reported mobile Safari failure was a black, long-running Walk the Pier entry. Desktop WebKit eventually loaded the old child, so the actual phone failure was not reproduced. The previous entry nevertheless required over 23 MB of image/runtime resources, used full-size scene textures, and had no application startup deadline or graphics-context recovery.

The scene now uses faithful, proportional sRGB display previews on coarse-pointer/small-screen devices. These previews are separate from the unchanged 104 collection records, their original URLs and full photograph files. The original source dimensions still control print proportions and the photographic camera. Desktop retains original scene textures. All 14 preview files and their existing-public-source hashes are recorded in mobile-scene-assets.json; build-scene-previews.py reproduces them.

Startup shows the real pier photograph and ordinary photograph links while modules load. Collections become usable before the deferred 3D module finishes. A healthy first graphics frame is required before the scene is reported ready. A 20-second startup deadline, unavailable WebGL, image/module failure, render errors, or context loss preserve a clearly labeled photographic fallback with collection and retry actions. Fallback is not a claim that the interactive walk succeeded. Rendering settles after scrolling stops; clear-glass reflection remains owned by the unchanged glass-sheen implementation.

Focused macOS WebKit 26.4 and Chrome 152 tests passed mobile collection tap, full-frame enlargement, return position, landscape, desktop walk, simulated graphics-context loss with retry, unavailable WebGL, and a stalled-module deadline. Loading and fallback panels were visually inspected, including their bounds and held-press position. All 104 records, ten slots, baseline and imported photograph hashes, and glass-sheen sources remained unchanged. Physical iPhone/mobile Safari recovery still requires a test of the published repair.

Hosting must include startup.js, scene-images.js, the changed runtime/CSS files, and all 14 scene-mobile JPEGs. The scene lookup uses the original filename, so existing host path prefixes remain supported. The optional per-record public URL in scene-images.js is reserved for a hosting adapter; it must not change collection URLs or source identities.
